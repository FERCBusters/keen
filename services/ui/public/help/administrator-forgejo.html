Forgejo

Enable and authenticate

Set KEEN_FORGEJO_ENABLED=true, KEEN_FORGEJO_BASE_URL and FORGEJO_TOKEN. The default FORGEJO_AUTH_MODE is token. Feed authentication can also use FORGEJO_USERNAME or FORGEJO_COOKIE where the selected mode requires it. Use the credentials appropriate to your server.

Select users, organisations or feeds

Open Admin → Sources & Evidence Mapping → By source → forgejo → Add collection. Select User and enter the account login, Organisation and enter the organisation login, or Feed and enter a specific repository feed URL. User discovery covers repositories owned by that user. Discovery repeats on each run and uses the token’s visibility.

Initial API activity collection looks back 14 days, subject to the upstream history available. Later runs use saved cursors. In a mapping rule, All collected events (any collection) selects events across the configured Forgejo collections. Configure at least one User, Organisation or Feed collection before running the ingester. The mapping editor’s Set up collections shortcut opens collection setup for the selected source.

Each named connection supplies its endpoint and credentials. Add repository or feed inputs to the appropriate connection. Repository activity is stored under activity; feed records can use rss. Inspect an actual event before choosing field paths.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is activity. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/forgejo.yml. See the common collection workflow for UI configuration and override behaviour.
