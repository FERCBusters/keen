Google Workspace

Google Workspace uses KEEN_GOOGLE_WORKSPACE_ENABLED, the configured service-account material and impersonation identity. Grant the required upstream scopes and delegation deliberately. Configure named streams with application, user key and system. Keep private-key material out of collection definitions and browser-visible settings.

Set GOOGLE_WORKSPACE_IMPERSONATE to the delegated administrator identity. Supply service-account material through GOOGLE_WORKSPACE_SA_KEYFILE, GOOGLE_WORKSPACE_SA_JSON or GOOGLE_WORKSPACE_SA_JSON_B64. A keyfile path must exist inside the running container.

Add named report streams under streams with the application and user key to query. The retained payload is under google_workspace; upstream report application and event type determine its content.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is google_workspace. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/google_workspace.yml. See the common collection workflow for UI configuration and override behaviour.
