Akamai Cloud (Linode)

Akamai Cloud posture reads the Linode account a personal access token belongs to: its users and their two-factor authentication, Cloud Firewalls, Linode backups, managed databases and LKE clusters, with read-only access, and records Cloud Manager sign-ins and account events. Results appear on the Akamai (Linode) vendor's Cloud posture tab (see Cloud vendor posture).

Keen reads api.linode.com through its validated HTTP client and names the account after its external unique ID, with the company name as its label.

Linode reports each user's latest sign-in attempt only. When that attempt failed, the user's last use is unknown and Unused users leaves the user out. The vendor page lists the account's users with their access, two-factor authentication and latest successful sign-in.

Activity

Keen records Cloud Manager sign-ins as login, with the address they came from, and the account's events under their own action names, such as user_create, firewall_update or linode_boot, with the user who acted and the resource. Linode keeps both for 90 days. Each read stops 15 minutes before the present.

1. Create a read-only personal access token

  1. Sign in to Cloud Manager as an unrestricted user: Linode lists users and sign-ins only to unrestricted users.
  2. Open your profile menu, choose API Tokens → Create a Personal Access Token, name it, for example Keen posture, and choose an expiry.
  3. Set Select All to No Access, then set the scopes below to Read Only, and create the token. Copy it at once: Cloud Manager shows it only once.

3. Verify, rotate or revoke

Recreate the API, worker and beat containers and choose Admin → Ingest runners → Run Akamai Cloud (Linode), then open the Akamai (Linode) vendor's Cloud posture tab. A check that reads Not established names its reason: not allowed means a scope is missing or the token belongs to a restricted user; not set up, or the credentials were not accepted covers a missing, expired or revoked token. Before the token expires, create another, update LINODE_TOKEN, recreate the containers and revoke the old token under API Tokens.
