IMAP mail

Use IMAP to collect new messages from a mailbox as evidence. Create one named connection per account and folder; several connections can use different mailboxes. IMAP is unavailable in demo environments.

  1. Set KEEN_IMAP_ENABLED=true for API, worker and beat. Keep KEEN_INTEGRATION_SECRET_KEY consistent on the workers. Start the dedicated worker with docker compose --profile imap up -d. For local builds use docker compose -f docker-compose.yml -f docker-compose.build.yml --profile imap up -d --build.
  2. Open Admin → Sources & Evidence Mapping → Define a source. Choose IMAP mail, name the connection, and enter its hostname, port (normally 993), username, password or app password, and folder (normally INBOX). Set Collection interval for that connection: the default and minimum are 5 minutes, with five-minute increments up to 1,440 minutes (24 hours). The account needs permission to read the chosen folder. Providers requiring OAuth-only authentication need another supported collection route.
  3. Leave Fetch message body off for headers only, or enable it and choose a character limit. The default is 4,000 characters; the supported range is 1–65,536. Plaintext is preferred within the message body. Related MIME resources are excluded; a related body whose root cannot be identified is omitted. If only HTML is available, it is retained as raw text inside JSON and never rendered. Attachments are excluded.
  4. Choose Collect now to establish the current mailbox position. Existing mail is not imported. The scheduler checks every five minutes and each connection polls when its configured interval has elapsed. Another Collect now queues a poll for that connection. Both manual actions and scheduled runs respect the interval from the last attempt, including failed attempts; a request made too early is skipped. Changing the interval retains the mailbox checkpoint. Actual collection can occur on a later scheduler tick or after a queue delay. To poll all enabled IMAP connections, use Admin → Ingest runners → Run IMAP. This queues background work; the confirmation means it was queued, not that collection finished. Inspect each connection’s collection health for results. The button is hidden when IMAP is disabled. Paused ingestion must be resumed first. Connection order rotates to share worker capacity. Busy queues can delay polling beyond five minutes. Collection leaves messages unread and does not delete or move them.
  5. Inspect Events for source imap and your connection. The summary includes the subject, the actor uses From (up to 128 display characters), and the action is mail.received. The event timestamp records collection time; the supplied Date header remains in mail.headers.date. Use connection-specific mapping rules and structured fields such as mail.headers.subject or mail.body to link evidence to controls.

Only verified implicit TLS is supported. Fix an invalid/expired certificate at the server; verification cannot be disabled. Private destinations require explicit entries in KEEN_INGESTION_ALLOWED_CIDRS. Loopback and link-local addresses remain prohibited. Passwords are encrypted; blank password fields preserve an existing credential. Changing the host, port or username requires re-entering it. File-managed connections use type imap, configuration fields host, port, username, folder, fetch_body, body_max_chars and poll_interval_minutes, an empty inputs object, and a password secret reference. Store configuration values as strings, including "true" or "false".

Each poll handles at most ten messages within a 100-UID window, up to 4 MiB of responses, and a 45-second collection alarm that also stops slow-drip responses; the parent terminates a stalled collector subprocess after 55 seconds. Headers and MIME metadata have separate bounds. The collector may return fewer messages to keep its serialised JSON output within 5 MiB; remaining messages are picked up by a later poll. Unicode escaping can use more output bytes than the original message text. Unsolicited literals and additional literals within one fetch are rejected before their payload is read. Contradictory mailbox UID metadata stops the poll. Only a bounded partial body is fetched; mail.body_truncated records truncation and mail.body_omitted_reason explains omissions. The JSON artifact contains selected headers and the optional body. The actor and system display labels are limited to 128 characters after redaction and masking; fuller bounded header values remain in the payload and artifact. Unsupported body charsets or invalid/unsupported transfer encodings omit the body with reason invalid_or_unsupported_body_encoding; headers are retained and later mail can still be collected. Supported body charsets are UTF-8, ASCII, Latin-1 and Windows-1252. Headers-only polling avoids MIME body structure entirely. KEEN applies configured sensitive-key redaction and privacy masking before storage. Body collection can retain personal or confidential prose: choose the folder, limit and retention policy accordingly.

Failed polls keep their checkpoint and use exponential backoff from two minutes to one hour. The next attempt waits for both that backoff and the configured collection interval to elapse. Inspect the worker result and logs for the generic failure, verify credentials/TLS and investigate oversized headers or malformed MIME structure in the mailbox. Disabling body collection avoids BODYSTRUCTURE failures while continuing to collect headers; protocol identity or size failures still stop the poll. The dedicated worker must be running to consume the imap queue; the ordinary worker does not consume it. If the server changes UIDVALIDITY, collection pauses. Review the mailbox, disable the old connection and create a replacement to establish a new baseline. Replacing or changing the account/folder can leave earlier uncollected mail outside that baseline. There is no automatic historical backfill.
