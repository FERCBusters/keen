Sources, collections and evidence mapping

The Workspace menu separates three jobs. API ingester builder defines custom API requests, authentication, pagination and normalized event fields. Sources & evidence mapping configures remote collection inputs and maps resulting events to framework controls and clauses. Ingest runners starts configured built-in adapters immediately; Diary Evidence records human-entered evidence.

The Sources view lists named servers and accounts. Choose Define a source, enter its name, endpoint and credentials, then add inputs. Database-managed credentials are encrypted using KEEN_INTEGRATION_SECRET_KEY. Environment-backed sources appear when they have configured inputs; file-managed sources use their deployment configuration. After saving an input, the confirmation offers Collect now and Add mapping rule. Each input also offers Add mapping rule. Webhook sources display a receiving URL and can be mapped directly. Custom API ingesters retain their dedicated builder.

Add collection opens a separate editor for repositories, organisations, users, feeds, queries or other inputs. Saving a collection does not require a mapping rule. View definitions filters the evidence mapping library to the source. A definition chooses which events match and which controls or clauses receive their evidence.

Deleting an API connection removes its collectors, revisions, run history, source-specific definitions and automatic evidence-to-control links. Clearing a built-in connection empties its saved collection lists and removes its source-specific definitions and automatic links. The confirmation shows affected definitions and counts and requires the connection name. Events, artifacts, manual/imported mappings and shared cross-source rules remain. Environment credentials are unchanged. API runs in progress block deletion; wait for completion and preview again. A changed preview must be reviewed again before removal.

Connect and verify a source

  1. Follow the source chapter to enable the adapter and configure credentials. Apply environment settings to the API, worker and beat containers, then recreate affected containers.
  2. Open Sources & Evidence Mapping, expand the source catalogue or use the source/connection view, and choose Add collection. Select the remote objects to collect.
  3. Use Ingest runners for a small test. Inspect the collection result and one actual event.
  4. Create a mapping from the event, or use the mapping builder. Preview its matches before saving.

Collection inputs decide what KEEN fetches. Mapping rules attribute the collected events to framework controls or clauses. An all-events mapping still needs a configured collection.

Web-UI configuration overrides the corresponding YAML file once saved. Administrators can manage YAML before creating an override. Source chapters identify the relevant file; Rules and YAML explains mapping export. Scheduling and pauses covers run timing and saved cursors. Storage and retention covers evidence artefacts.

Named source connections

Each connection holds an endpoint or account, authentication and input definitions. Loki URLs and optional authentication belong to the connection; LogQL queries are inputs. Google Workspace connections hold a service-account JSON credential and delegated administrator. CloudWatch connections hold an AWS region and account credentials.

Database credentials are encrypted using KEEN_INTEGRATION_SECRET_KEY. Set the same key on API and worker and preserve it for recovery. Blank credential fields preserve saved values on edit. KEEN_SOURCE_CONNECTIONS_FILE supplies additional YAML or JSON connections using environment-variable or secret-file references. Mount the configuration and referenced secrets on API and worker. Existing environment settings supply the Environment default connection.

The KEEN_<TYPE>_ENABLED flag gates all connections of that type. KEEN_WEBHOOKS_ENABLED gates webhook receipts. A named connection can also be disabled individually. Scheduled polling uses the source type’s cadence; Run connection starts a manual run through the same gates. Connection identities scope cursors, event deduplication, artifact keys and webhook replay protection.

IMAP mail

Use IMAP to collect new messages from a mailbox as evidence. Create one named connection per account and folder; several connections can use different mailboxes. IMAP is unavailable in demo environments.

  1. Set KEEN_IMAP_ENABLED=true for API, worker and beat. Keep KEEN_INTEGRATION_SECRET_KEY consistent on the workers. Start the dedicated worker with docker compose --profile imap up -d. For local builds use docker compose -f docker-compose.yml -f docker-compose.build.yml --profile imap up -d --build.
  2. Open Admin → Sources & Evidence Mapping → Define a source. Choose IMAP mail, name the connection, and enter its hostname, port (normally 993), username, password or app password, and folder (normally INBOX). The account needs permission to read the chosen folder. Providers requiring OAuth-only authentication need another supported collection route.
  3. Leave Fetch message body off for headers only, or enable it and choose a character limit. The default is 4,000 characters; the supported range is 1–65,536. Plaintext is preferred. If only HTML is available, it is retained as raw text inside JSON and never rendered. Attachments are excluded.
  4. Choose Collect now to establish the current mailbox position. Existing mail is not imported. New messages are polled every five minutes; another Collect now starts a manual poll. Collection leaves messages unread and does not delete or move them.
  5. Inspect Events for source imap and your connection. The summary includes the subject, the actor uses From, and the action is mail.received. The event timestamp records collection time; the supplied Date header remains in mail.headers.date. Use connection-specific mapping rules and structured fields such as mail.headers.subject or mail.body to link evidence to controls.

Only verified implicit TLS is supported. Fix an invalid/expired certificate at the server; verification cannot be disabled. Private destinations require explicit entries in KEEN_INGESTION_ALLOWED_CIDRS. Loopback and link-local addresses remain prohibited. Passwords are encrypted; blank password fields preserve an existing credential. Changing the host, port or username requires re-entering it. File-managed connections use type imap, configuration fields host, port, username, folder, fetch_body and body_max_chars, an empty inputs object, and a password secret reference. Store configuration values as strings, including "true" or "false".

Each poll handles at most ten messages within a 100-UID window, up to 4 MiB of responses, and a 45-second network deadline; a stalled collector subprocess is terminated after 55 seconds. Headers and MIME metadata have separate bounds. Only a bounded partial body is fetched; mail.body_truncated records truncation and mail.body_omitted_reason explains omissions. The JSON artifact contains selected headers and the optional body. KEEN applies configured sensitive-key redaction and privacy masking before storage. Body collection can retain personal or confidential prose: choose the folder, limit and retention policy accordingly.

Failed polls keep their checkpoint and back off from two minutes to one hour. Inspect the worker result and logs for the generic failure, verify credentials/TLS and investigate oversized or malformed messages in the mailbox. The dedicated worker must be running to consume the imap queue; the ordinary worker does not consume it. If the server changes UIDVALIDITY, collection pauses. Review the mailbox, disable the old connection and create a replacement to establish a new baseline. Replacing or changing the account/folder can leave earlier uncollected mail outside that baseline. There is no automatic historical backfill.
