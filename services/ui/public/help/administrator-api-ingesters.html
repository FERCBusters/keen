Custom API ingesters

Chapter 22 of 27

Build a custom API ingester

Open API ingester builder to define a connection and requests for an HTTP service. Use this for a bespoke API or a resource that the built-in adapters do not collect.

  1. Configure a custom connection with its base URL and supported authentication. Credentials are stored encrypted using KEEN_INTEGRATION_SECRET_KEY; set this key consistently for API and workers and include it in protected backups.
  2. Define the request path, query parameters, supported request payload and pagination settings. Start with a bounded page size and a small collection.
  3. Select the records to extract and configure their normalised event fields, including stable identity and timestamp information.
  4. Test the request, inspect the resulting event, then configure its collection schedule.
  5. Create an evidence mapping in Sources & Evidence Mapping and preview it against the collected events.

The builder uses declarative request and field configuration. Outbound network restrictions, credential handling and request limits still apply. A remote API’s permissions and history determine the evidence available. Custom connection objects appear in the builder’s credentials list; built-in sources have their own credential editor under Sources & Evidence Mapping.

Keep mapping rules focused on what the event demonstrates. The rules chapter explains revision management, YAML export and historical mapping. Demo installations without the integration secret key cannot configure custom API credentials.

Delete ingesters and connections

Open the API ingester builder. Choose Delete ingester on the relevant card to remove one ingester, or Delete connection beside the saved connection to remove it and its ingesters. Connections can also be removed from Sources & Evidence Mapping.

  1. Read the impact preview. It lists the affected ingesters and source-specific mapping rules, together with the number of automatic evidence-to-control links.
  2. Check that the selected item is the one you intend to remove. Type its displayed name exactly and choose Delete ingester or Delete connection. Cancel closes the preview and keeps the configuration.
  3. Review the refreshed list. Collected events, evidence artefacts, measurements, manual and imported mappings, and shared cross-source rules remain available.

Deleting an ingester removes its saved revisions, queued jobs and run history, its source-specific rules and automatic mappings for its events. Its connection and sibling ingesters remain available. Deleting a connection additionally removes its encrypted credentials and all ingesters attached to it, together with their revisions and run history.

An active run must finish before deletion. If the configuration or mapping counts change after the preview, open a fresh preview and review the impact again. A connection referenced by another ingester’s published revision stays protected until that ingester is republished using its replacement connection.
