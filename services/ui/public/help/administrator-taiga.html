Taiga

Taiga uses enabled/base URL settings and its configured token or supported credentials. Add project IDs and labels in the application. Confirm the upstream account can read the intended projects.

Set KEEN_TAIGA_ENABLED and KEEN_TAIGA_BASE_URL; the token alias is TAIGA_TOKEN. Configure projects with project identifiers and optional labels. Inspect the project activity returned by the upstream identity before broadening the collection.

Payloads retain the activity entry and recognised extracted values. These fields vary with the activity type.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is entry. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/taiga.yml. See the common collection workflow for UI configuration and override behaviour.
