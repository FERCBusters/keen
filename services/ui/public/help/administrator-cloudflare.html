Cloudflare

Cloudflare is a built-in, read-only ingester for Cloudflare account audit logs (version 2). It collects who did what in a Cloudflare account and its zones, in the dashboard or through the API: changes to DNS records, settings, API tokens and members, views of configuration, and actions Cloudflare's own systems took.

Create an API token and configure Keen

  1. In the Cloudflare dashboard, create an API token for Keen alone, either an account API token or a user API token. Give it one permission, Account Settings Read, for the one account Keen reads, and copy the token: Cloudflare shows it once.
  2. Copy the account ID from the account's overview in the dashboard: 32 lowercase hexadecimal characters.
  3. Set these in Keen's .env and recreate the API, worker and beat containers: 
    KEEN_CLOUDFLARE_ENABLED=true
KEEN_CLOUDFLARE_ACCOUNT_ID=0123456789abcdef0123456789abcdef
KEEN_CLOUDFLARE_API_TOKEN=YOUR_API_TOKEN
KEEN_CLOUDFLARE_CONFIG_PATH=/app/config/cloudflare.yml
KEEN_CLOUDFLARE_POLL_SECONDS=900

Cloudflare collection is off until KEEN_CLOUDFLARE_ENABLED is true. Create a named Cloudflare source for each Cloudflare account; the Environment default connection uses the deployment settings. Keen takes an API token alone, never a Global API Key: a token that holds only Account Settings Read can read the audit log and change nothing in Cloudflare.

Going deeper: transport security

Keen sends requests to Cloudflare's own API alone, https://api.cloudflare.com/client/v4; no setting or connection field names another server. The token is sent as a bearer token and never appears in a URL. The account ID is part of every request's path, so Keen accepts it only as 32 lowercase hexadecimal characters, when a source is saved and again before each run.

HTTPS and certificate verification are mandatory, redirects are refused, cookies Cloudflare sets are discarded, each request ends within two minutes and responses are limited to 8 MiB. A saved token is write-only.

Select the stream in Keen

Define a Cloudflare source with the account ID and the API token, then select Add input on that source in Sources & evidence mapping. Cloudflare offers one stream here, the account audit log, so there is nothing to choose. An optional label becomes the event's system; otherwise it is Cloudflare. The shipped stream list is empty, so enabling the adapter alone collects nothing; add the stream, then use Ingest runners → Run Cloudflare or wait for the scheduled run.

Going deeper: the YAML file and its settings

Administrators can also manage config/cloudflare.yml; saved web-UI configuration overrides it.

ui_name: Cloudflare
badge_color: '#F38020'
streams:
  - stream: audit
    # label: Production account
initial_lookback_days: 30
window_hours: 24
overlap_minutes: 60
max_pages: 100
page_size: 500

initial_lookback_days is how far back the first run reads (0 to 367). window_hours is the span of the log read at a time (1 to 168), overlap_minutes how far each window reaches back for entries Cloudflare lists late (0 to 1,440), max_pages the pages one run reads (1 to 1,000) and page_size the entries asked for in each page (1 to 1,000). Lower page_size if a page reaches the 8 MiB limit.

Going deeper: windows, pages and limits

Keen reads the log in windows of time, oldest first, from its cursor to the present, and asks for each window's entries oldest first. Each page of a window is stored and committed before the next is requested, and the cursor moves to a window's end only when every page of it is stored, so a failure never skips entries. A run that reaches max_pages inside a window keeps its place, and the next run continues that window. A paging value Cloudflare no longer accepts is replaced by reading the window again from its first page.

Cloudflare does not state how soon an action appears in the log, so each window reaches back overlap_minutes before its start. Cloudflare gives each entry an identifier, so an entry read twice is stored once. A page without entries ends its window.

An entry without a readable time is dated when it was collected, and one that is not an entry object is left out and counted as invalid_records in the run's result. An answer that does not report success, or that Keen cannot read, is reported as an error and keeps the cursor, as do HTTP 429 and transient failures, which the next scheduled run retries.

Going deeper: what an entry holds and what Keen keeps

An entry names who acted, by email address, Cloudflare identifier and IP address, the request's method, path, status, user agent and Ray ID, and, for many changes, the request Cloudflare received and its answer. Keen keeps the whole entry under event in the payload and in the artifact, through the standard Keen redaction, masking, artifact storage, SHA-256 and framework-rule pipeline.

Redaction withholds values under names it treats as secrets, such as an API token's token_id and token_name, so an action taken with an API token names its actor by Cloudflare's identifier. An API token, a tunnel's token and a Worker's secret can appear in a request or an answer under ordinary names, so for any resource whose product or type is named like a secret, and any entry whose request was made at a path named like one (such as a Worker's secrets), Keen withholds the request and the answer altogether and keeps the rest of the entry.

Version 2 of the log records views as well as changes. The Cloudflare dashboard hides views by default; Keen collects them, so expect many events, and choose the ones that matter with mapping rules.

Map Cloudflare evidence

Choose Create mapping, source cloudflare. Keen names each event's action after the Cloudflare product it concerns, or, for an action on a user's own profile, its scope, followed by the kind of action: create, update, delete or view. The event's actor is the email address of whoever acted, or Cloudflare's identifier for them, and its summary is Cloudflare's own description, with the zone it concerns.

Cloudflare actionEvent action
Create DNS Recorddns_records.create
LOGINuser.update
List Tokenstokens.view
List DNS Recordsdns_records.view

The outcome is Cloudflare's own result, success or failure, and a failure has severity 6, every other event 3. A product or action that is not a short plain name becomes unknown.

Example: source cloudflare, action dns_records.create, mapped to your change management control. A second mapping on action tokens.create records new API tokens against your access control.

Going deeper: useful JSON paths
  • event.action.description, event.action.type, event.action.result and event.action.time
  • event.actor.email, event.actor.type, event.actor.context (such as dash or api_token) and event.actor.ip_address
  • event.resource.product, event.resource.type, event.resource.scope, event.resource.request and event.resource.response
  • event.zone.name, event.raw.method, event.raw.uri and event.raw.status_code

Scope

This adapter reads an account's audit log, version 2. It does not read version 1 audit logs, organisation-level audit logs or Logpush jobs, it reads no traffic, firewall or analytics data, and it changes nothing in Cloudflare. Cloudflare keeps audit logs for 18 months; the first run reads back as far as initial_lookback_days. The source is unavailable in demo environments.
