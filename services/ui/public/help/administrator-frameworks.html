Administering KEEN

Organisation frameworks and risk library

Chapter 4 of 27

Choose organisation frameworks

In Administration → Frameworks, select the frameworks your organisation uses and choose a default. The workspace catalogue, navigation and mapping selectors show this selection. Administrators can still edit and re-enable any retained framework.

Set KEEN_ENABLED_FRAMEWORKS=ISO27001:2022,KEEN-AF:1.0 in .env to limit the choices available in Administration. An empty value allows every framework. Use exact slugs separated by commas. Unknown slugs are reported in Administration. If an environment change excludes all saved choices, the available environment frameworks are used until another selection is saved.

At least one framework must be selected in the UI. Hiding a framework retains its controls, audits, evidence and mapping rules. This controls workspace visibility; existing rules and explicit API operations still work. Disable rules that should stop mapping evidence. Reload open pages to refresh navigation; an unavailable previous selection falls back to the organisation default.

Manage frameworks and the risk library

Use Admin → Frameworks for normal framework maintenance. Select a framework or choose New framework, enter its slug and descriptive fields, and Save framework. Add Clause, Control or Custom nodes with references, titles, hierarchy, scope and related clauses. Save a small change and inspect the result before a broad edit.

Slugs and node identities are stable identifiers. The editor does not rename them in place. Deletion may be blocked by children, clause relationships or evidence mappings. Review the impact on linked risks, audits and other records before removing content. Do not use direct SQL deletion to evade a dependency check.

The migration chain seeds the bundled framework catalogues, including KEEN Assurance Framework (KEEN-AF:1.0), and the reusable risk library. Seed data is shipped with the release; migrations load the version included in that release. Framework and risk-library changes made in the application belong in PostgreSQL backups.

Risk register settings apply to the shared set of risk scenarios. The editor, register and heatmap use the same 1–5 likelihood and impact fields for inherent and residual scoring. Library templates are reusable starting points. Their suggested ratings and KEEN-AF control links need local review. Review existing risk assessments individually when a template changes.

Open Security Architecture framework catalogues

KEEN includes 92 frameworks. An offline snapshot from Open Security Architecture (OSA), dated 8 October 2026, supplies 88 catalogues. The other four are KEEN Assurance, UK Digital Verification Services Trust Framework, Cyber Essentials and Risk Ledger. OSA framework machine names and clause references match its API, including iso_27001_2022, soc2_tsc and hipaa_sr. Choose enabled frameworks in Admin → Frameworks; KEEN Assurance is enabled by default. Framework metadata and nodes remain editable in the application.

OSA’s data and KEEN’s catalogue adaptation are licensed under CC BY-SA 4.0, separately from KEEN’s software licence. Control details retain source references, coverage estimates, rationale and gaps. The catalogues provide OSA’s descriptions and assessments of the requirements. Follow the upstream publication links for authoritative normative text and applicable usage rights. The HIPAA catalogue covers the Security Rule.

KEEN derives cross-framework related-control links through shared NIST SP 800-53 references. Directly mapped evidence appears under related controls without duplicating events. Each event contributes once to a control’s count. Inheritance uses one hop: inherited evidence does not propagate onward through additional links. Shared references guide an overlap assessment. Review the linked requirements and supporting evidence for your own assurance decisions. KEEN’s existing reviewed links to its own frameworks are attributed separately.

Fresh installations enable only KEEN Assurance Framework by default; other imported frameworks start disabled. Use Admin → Frameworks to select enabled frameworks and the organisation’s default. Select all and Deselect all change the pending selection; Save applies it. Environment restrictions still apply, and at least one framework must be selected. Distinctive card colours help identify frameworks. Edit imported framework descriptions and controls, add local controls, or create new frameworks. Ordinary restarts never overwrite those changes. The control page displays source details and the related-control crosswalk.
