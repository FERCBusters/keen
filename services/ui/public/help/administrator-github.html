GitHub

GitHub supports organisation, repository and feed inputs. Configure KEEN_GITHUB_ENABLED and its base URL as required; secret aliases include GITHUB_TOKEN and GITHUB_USERNAME. Review upstream API quotas and restrict repository access to the intended scope.

Add organizations, repos or feeds collections in the source view. An organisation collection can select organisation events, repository events through repository discovery, or the organisation audit log. Its include setting defaults to events; all selects organisation and repository events. Audit collection must be selected explicitly and requires the upstream audit-log permissions. Repository collections use repository activity. Use a token with access to the intended organisation/repositories. Audit-stream access also depends on the upstream account and permissions.

Event payloads use github_event, audit records use audit, and feed records use feed. GitHub API history and the adapter’s bounded page reads limit what can be recovered after a long outage. It does not retrieve every repository object or full Git history.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is github_event → type. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/github.yml. See the common collection workflow for UI configuration and override behaviour.
