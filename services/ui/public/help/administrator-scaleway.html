Scaleway

Scaleway posture reads one Organization: its members' MFA, the owner and IAM managers, API key age, Instance security groups, Managed Database exposure and backups, and Kubernetes Kapsule clusters, with read-only access, and records Audit Trail API and authentication events. Results appear on the Scaleway vendor's Cloud posture tab (see Cloud vendor posture).

Keen reads api.scaleway.com through its validated HTTP client with an API key that belongs to an IAM application, sends the secret key in the X-Auth-Token header, and names the Organization in every listing.

Security groups are read in each zone of KEEN_SCALEWAY_ZONES, and Database Instances and clusters in those zones' regions. A policy's permission sets count whichever Projects its rules cover. The vendor page lists the Organization's members with their role, MFA and last sign-in.

Activity

Keen records Audit Trail API events under the method's name, such as CreateAPIKey or DeleteServer, with the member or application that called it and an outcome from the response status, and authentication events as SignIn, with the sign-in method, the MFA type and any failure reason. The stored record leaves out request bodies and members' telephone numbers. Keen reads Audit Trail in fr-par and nl-ams, the regions that offer it. Each read stops 15 minutes before the present.

1. Create an IAM application, its policy and an API key

  1. In the Scaleway console, open IAM → Applications → Create application, name it, for example keen-posture, and create it without a policy.
  2. Open IAM → Policies → Create policy, name it, for example keen-posture-read, and choose the application as its principal. Add one rule scoped to the Organization with the Organization permission sets below, and one rule scoped to All current and future Projects with the Project permission sets.
  3. Open IAM → API keys → Generate an API key, choose the application as its bearer and set an expiry. Copy the secret key at once: the console shows it only once. Note the Organization ID from Organization settings.

2. Configure Keen

SettingPurpose
KEEN_SCALEWAY_ENABLEDTurns Scaleway posture on.
KEEN_SCALEWAY_ORGANIZATION_IDThe Organization ID from step 3.
SCALEWAY_SECRET_KEYThe API key's secret key from step 3. The access key is not needed.
KEEN_SCALEWAY_ZONESThe zones to read, separated by commas, such as fr-par-1,nl-ams-1; up to 20. Blank reads every zone in Paris, Amsterdam and Warsaw.

3. Verify, rotate or revoke

Recreate the API, worker and beat containers and choose Admin → Ingest runners → Run Scaleway, then open the Scaleway vendor's Cloud posture tab. A check that reads Not established names its reason: not allowed means a permission set is missing from the application's policy; not set up, or the credentials were not accepted covers a missing or expired key, a wrong Organization ID and an unknown zone. Before the key expires, generate another for the same application, update SCALEWAY_SECRET_KEY, recreate the containers and delete the old key under IAM → API keys.
