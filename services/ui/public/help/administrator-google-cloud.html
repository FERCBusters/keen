Google Cloud

Google Cloud posture reads one organisation, or one project where there is no organisation, with read-only access, and records its Admin Activity audit log entries for IAM, service account and organisation policy changes. Results appear on the Google Cloud vendor's Cloud posture tab (see Cloud vendor posture).

Keen reads it as a service account through a certificate-validating HTTPS-only Google transport, and every request names the configured organisation or project. People sign in with Google accounts, whose 2-Step Verification the Google Workspace provider checks.

The vendor page lists the holders of Owner and Organization Administrator with their roles.

Activity

Keen records Admin Activity audit log entries for SetIamPolicy, service account and service account key creation and deletion, and organisation policy changes, under the method's name, from the organisation or project and any projects in KEEN_GOOGLE_CLOUD_PROJECTS. Each read stops 15 minutes before the present.

1. Create the service account and grant its roles

  1. In a project you use for administration, create a service account, for example keen-posture, and create a JSON key for it under Keys → Add key.
  2. Grant it these roles on the organisation (or on the project, without an organisation), under IAM & Admin → IAM → Grant access:
roles/cloudasset.viewer
roles/iam.securityReviewer
roles/orgpolicy.policyViewer
roles/securitycenter.findingsViewer
roles/logging.viewer
roles/serviceusage.serviceUsageConsumer
RoleNeeded by
roles/cloudasset.viewerOwners and organisation administrators, Service account keys and both network checks
roles/iam.securityReviewerOwners and organisation administrators, and Data Access audit logs
roles/orgpolicy.policyViewerThe three organisation policy checks

2. Configure Keen

SettingPurpose
KEEN_GOOGLE_CLOUD_ENABLEDTurns Google Cloud posture on.
KEEN_GOOGLE_CLOUD_ORGANIZATIONThe organisation's number, such as 123456789012.
KEEN_GOOGLE_CLOUD_PROJECTWithout an organisation, the project ID to read instead.
KEEN_GOOGLE_CLOUD_PROJECTSProject IDs, separated by commas, whose own Admin Activity entries are read as well; up to 50.
GOOGLE_CLOUD_SA_JSON_B64, GOOGLE_CLOUD_SA_JSON or GOOGLE_CLOUD_SA_KEYFILEThe service account key from step 1, as base64, as JSON, or as a file path inside the container. Its token endpoint must be HTTPS.

3. Verify

Recreate the API, worker and beat containers and choose Admin → Ingest runners → Run Google Cloud, then open the Google Cloud vendor's Cloud posture tab. A check that reads Not established names its reason: not allowed means a role is missing; not set up, or the credentials were not accepted covers a missing setting or key, a disabled API and an organisation number that does not match.
