Elasticsearch

KEEN collects log documents from Elasticsearch using index, alias or data stream patterns and the point-in-time search API. The collector targets the Elasticsearch 8.19 and 9.x APIs. Each named source holds its HTTPS endpoint and credentials. Each input selects a pattern and optional message filter.

Connect and collect

  1. Set KEEN_ELASTICSEARCH_ENABLED=true on the API, worker and scheduler, and recreate those containers.
  2. In Admin → Sources & evidence mapping → Sources, choose Define a source, select Elasticsearch, and enter a source name and HTTPS base URL, such as https://search.example.org:9200.
  3. Enter either an encoded Elasticsearch API key (without the ApiKey prefix), or a username and password. Give the account read access only to the required indices, aliases or data streams. Clear saved credentials for the previous authentication method when switching methods. HTTPS certificate and hostname verification are mandatory; private certificates require a trusted CA.
  4. Add an input with a distinct name and an index pattern, such as logs-*. Comma-separated patterns are supported. The optional message filter uses Elasticsearch simple-query-string syntax against the selected message field. For example, "authentication failed" | "access denied" matches either phrase. A blank filter collects every document in the selected time window.
  5. Confirm the field mappings. Defaults are @timestamp, message, host.name, user.name, event.action and event.outcome. The timestamp must be a single Elasticsearch date/date_nanos field with doc values enabled, and documents must have _source enabled.
  6. Choose Collect evidence now, inspect an event, and add a mapping rule for the source or its input. Structured document fields remain available to mapping conditions.

Collection windows and deduplication

Scheduled collection runs every 30 minutes. The first run begins 24 hours back. Each run processes up to four one-hour windows and overlaps the previous completed cursor by five minutes to collect delayed records. Delays longer than the overlap can be missed; an upstream ingestion timestamp is useful for delayed log delivery. Connection, index and document ID identify an event. Repeated documents are deduplicated, including across overlapping inputs on that connection; the first collecting input supplies the event's input identity. Stored evidence represents the first collected version of a document.

Input limits and retries

Additional input settings accept initial_lookback_minutes (1–43200), overlap_minutes (0–60), window_minutes (1–1440, greater than the overlap), page_size (1–1000), max_pages (1–100) and windows_per_run (1–24). Defaults are 1440, 5, 60, 500, 100 and 4 respectively. Collection has a two-minute connection budget. Partial searches and failed windows retain their previous cursor; already saved documents deduplicate on retry. If an input reaches its page or time limit, reduce its window or narrow its filter. Changing the pattern, filter or field mappings starts a fresh bounded backfill.

Environment-managed sources

Environment-managed collection uses KEEN_ELASTICSEARCH_BASE_URL, KEEN_ELASTICSEARCH_API_KEY or KEEN_ELASTICSEARCH_USERNAME/KEEN_ELASTICSEARCH_PASSWORD, with a queries list in config/elasticsearch.yml. The same input structure works in named connections supplied through KEEN_SOURCE_CONNECTIONS_FILE. The source type's enabled flag gates every connection.
