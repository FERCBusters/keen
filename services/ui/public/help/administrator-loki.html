Loki

Loki uses KEEN_LOKI_ENABLED, its base URL and configured basic or header authentication. Define named LogQL queries in the application and set normalised source/system/action/outcome/severity fields where appropriate. Initial lookback, maximum query range, overlong-range strategy and catch-up chunks constrain backlog processing.

Set KEEN_LOKI_BASE_URL. Basic authentication uses KEEN_LOKI_USERNAME and KEEN_LOKI_PASSWORD; header authentication uses KEEN_LOKI_HEADER_NAME and KEEN_LOKI_HEADER_VALUE. Each collection has a named LogQL query. Start with a narrow stream selector and a small time window.

The payload retains labels and line; JSON lines also expose json and, where recognised, extracted. Set catch-up limits according to upstream query capacity and inspect runner errors when a backlog stops advancing.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is labels → job. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/loki.yml. See the common collection workflow for UI configuration and override behaviour.
