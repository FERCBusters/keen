Jenkins

Jenkins uses KEEN_JENKINS_ENABLED, KEEN_JENKINS_BASE_URL, JENKINS_USERNAME and JENKINS_API_TOKEN. Define jobs by stable name. The job’s kind becomes the event action and label becomes its system. A condition looking for deploy will not match an event whose action is deployment; inspect the actual evidence and use the exact values on the collected event.

Add a jobs collection with the job’s name, label and kind. The current adapter constructs /job/<name>/api/json for simple top-level jobs. It examines up to 50 recent builds per run, so schedule collection frequently enough for the job’s build rate.

The payload contains job, build, label and kind. For example, build → result exposes the upstream result, while the event’s outcome contains KEEN’s normalised result.

Inspect and map evidence

Inspect a collected event and use Create mapping from this event. Structured selectors expose the payload that this source actually returns; a useful starting path is build → result. Action and outcome filters use KEEN’s normalised event values. Preview matching and non-matching examples.

For file-managed deployments, collection inputs live in config/jenkins.yml. See the common collection workflow for UI configuration and override behaviour.
